# Status

Type: PRODUCT
Authority: What this version does. Refuse lines live in [roadmap](roadmap.md). Pipeline shape lives in [architecture](architecture.md).

Dossier 0.9 writes a posting-shaped CV or letter from spanned approved cards (`dossier tailor`). 0.8 added thin-user sources and hybrid ask over passage vectors in `evidence.db`. Retrieval still prefers a quote. When full text is empty or thin, a high-cosine neighbor can supply the sentence. When one span is not enough, it can stitch compound questions, hop on seeker headers (`ask.hops`, default 1), and call a local model (completion budget unlimited by default; set `DOSSIER_LLM_MAX_CALLS` to cap). `dossier index` embeds passages with Ollama. `ask.pubs` is off unless you turn it on. The pubs adapter reads the Zotero collection named in config. Fixture tests are green. A full warehouse prove is still a human step.

## Works

- SQLite corpus and claim cards (`pending`, `approved`, `refused`) under `data/evidence.db`. Accepted and refused answers are stored in the same file and are not claim cards. Long records are split into passages stored beside them.
- Refuse rule: no citation, a citation that is not in the corpus, or evidence text that does not carry the sentence.
- CLI: `ingest`, `extract`, `buffet`, `approve`, `refuse`, `reopen`, `review`, `gui`, `ask`, `brief`, `run`, `span`, `defend`, `gaps`, `packet`, `tailor`, `match`, `index`, `prove`, `doctor`, `referees`. `gui` needs the `[web]` extra.
- `approve <card-id>` and `refuse <card-id>` change one pending card. `reopen <card-id>` sends an approved or refused card back to pending. `--all` with `--source` and `--except` does the same for a set. `review` is a loopback page that groups cards by source, lens, and kind, searches claim text, and shows a short snippet from the first citation. It does not write spans.
- `match` reads a local job spec (`dossier match --posting`, or the workbench Match page) and writes `data/matches/<stamp>.md`. Requirements stay in spec order, at most 20: bullets, numbered lines, and sentences with a requirement cue. Boilerplate sections (about us, benefits, how to apply, equal opportunity, salary) drop unless a line there is itself a cue. Each requirement lists up to five quotes, at most two from the same source. A quote is the sentence that carries the requirement, or a passage neighbor at cosine 0.82 or higher. An approved card whose stored span carries the requirement is listed first. Records without a card still appear. A requirement with no such sentence stays in the list as a gap (`no carrying evidence`, or `requirement is too broad` when every content word is generic). A spec with no bullets and no cues is one `unsplit` requirement. Passage search is the locker search `ask` uses, and match also fuses passage neighbors when vectors for this model already exist. That query embedding does not spend `DOSSIER_LLM_MAX_CALLS`. No completion. Provider `off` still returns the lexical list. The command does not approve a card. `tailor` still writes the CV or letter. `brief` still answers a question pack. Ask, match, and brief can narrow sources, a year range, and effort for that command (`--sources`, `--year-from`, `--year-to`, `--effort`). The workbench shows the same controls on those pages. Defaults are `[scope]` in `dossier.toml` and the effort preset; a profile stores both. Leave sources unset to search every registered source. Unchecking every source searches none. A record with no Year header stays in when a range is set.
- `tailor` reads a local posting and writes `data/drafts/<stamp>.md`. A CV groups matched spanned approved cards by lens. A letter prints those spans in rank order. Pending cards stay out. Approved cards with no span are listed and not quoted. Coverage names posting kinds and skills that have a card, and those that do not. `--arrange` is letter-only and off by default: one completion may emit only the selected spans plus “I am applying for the role in the posting.” Any other sentence keeps the deterministic letter. A CV name comes from `DOSSIER_CV_NAME` or `[tailor] name`. A subtitle is the LinkedIn position title only when the corpus has exactly one. No PDF.
- `prove` — disposable `DOSSIER_DATA`, capped adapters (default linkedin/chatgpt/applications), exact brief, defend/packet, ask smoke, `ledger.json`. Never approves. Fails closed without FTS5 unless `--allow-overlap`.
- Optional `$DOSSIER_DATA/dossier.toml` (gitignored). Environment variables override it. `dossier.example.toml` lists the knobs. Defaults: Ollama on loopback, `ask.mode = auto`, full text on, extract may call the model, and model calls are unlimited unless `max_calls` or `DOSSIER_LLM_MAX_CALLS` is a positive cap. Include and exclude phrases for each adapter are on without that file. A list adds phrases; the matching `_off` key turns a built-in phrase off. The workbench Phrase lists page writes those keys. Invalid TOML fails load with exit code 2 (`FAIL:` on stderr) instead of silently using empty config. Detail: [seekers](seekers.md).
- `extract` writes a pending card from LinkedIn rows, from seeker records that already carry a Lens and Kind header, and from employer, git, and ChatGPT text when one sentence is already in the record. It uses only words in that record. Records that already have a pending or approved card are left alone. The model sees only what is left, and only when extraction is on and the provider is not `off`.
- `ask` modes: `exact` quotes a span and never calls a model; `auto` (default) tries an approved claim only when that claim contains every content word of the question and one of those words is specific (a shared "held", "work", "record", or "publish" is not an answer), then a quote, then up to `ask.hops` hops (default 1) on `Lens`/`Kind` that may open sibling records and quote any of them, then one completion when several hits tie or the span will not carry the question; `rich` always composes when there are hits unless an approved claim already carries the question. Retrieval uses SQLite FTS5 on title, text, and passages when that module is built in. Whole-word overlap is the fallback when full text cannot run, and it breaks ties when it can. When full text hits exist but none sit inside the current source or lens filter, overlap inside that filter is used. An empty full-text result stays empty. A `--source` that already holds only a small set of records is still listed when the question's words miss. An empty or thin full-text result can add a passage-vector neighbor from `dossier index`. A neighbor without a carrying sentence, and without a high cosine, stays a refusal. A token inside a longer word does not count. Compound questions can split into at most four parts. The answer is printed only when every citation is one of the hits and the cited text can carry the sentence. No hits, an empty question, a citation outside the hits, or an unsupported sentence is a refusal. `--source`, `--lens`, and `--kind` limit the search. At most 8 hits go into the prompt. `--follow` adds up to three earlier accepted answers as context. Those lines are not citations.
- `brief` runs the built-in `career` pack, a local `posting` pack, or a JSON pack you pass, and writes `data/briefs/<stamp>.md`. The career questions list positions, skills shown in use, document files spread across years (not only the newest three per kind), employer career folders (`publications` / `events` / `projects` / `slides`) at read time, and publication-shaped records already in the corpus. After a refusal of any other question it may add one closed follow-up. `run` ingests adapters it can already detect, drafts cards, optionally extracts, writes that brief, and prints a ledger of records, skipped adapters, model calls, and whether egress was possible. Neither command approves a card.
- `span` prints the shortest non-header sentence that carries a claim, plus the record title and URI. `--uri` and `--source` narrow the search. No model. An empty claim, or no single sentence, is a refusal.
- `defend` walks pending and approved cards. When one cited record contains that sentence, it stores `span` and `span_uri` on the card. It does not change status and it does not approve. Cards with no such sentence print as `unspanned`. The whole-record check can still pass when the words are spread across sentences; `span` and `defend` require one sentence.
- `gaps` counts seeker `Lens` and `Kind` headers on records, lists lenses with zero records, and lists approved cards that are the only spanned card for their lens and kind. It also names an ingest hint for an empty lens, approved cards with no span, and records with no open card. It does not run those commands and it does not approve. No model.
- `packet` writes `data/packets/<stamp>.md` from approved cards that already have a span: the claim, lens and kind when present, the sentence as a quote, and the URI. Approved cards without a span are listed under “Not included” and are not quoted. No model.
- `index` embeds passages into `evidence.db` with Ollama `POST /api/embed`. Provider `off`, a missing model, or a remote URL without `DOSSIER_LLM_ALLOW_REMOTE` leaves the table empty. One query embedding per ask does not spend `DOSSIER_LLM_MAX_CALLS`.
- `doctor` prints the data directory, python executable, SQLite version, whether FTS5 is available, the provider, whether egress is on (`no` until a remote LLM is opted in; a blocked non-loopback Ollama URL is still `egress: no` and does not print the remote notice), the call budget (`0` means unlimited), embed model, vector count, whether ask-pubs is on, pubs URL, the pubs collection when set, how many employer folders and git repos are listed, the git author when set, how many spanned approved cards tailor can quote, and which adapters detect (pubs includes a row count from the named Zotero collection, or from `/search` when no collection is set and the server answers). It warns when Slack or meetings detect but identity is empty, when a pubs collection is set but `rows=0`, and when mbox records cite hard-closed folders (`mbox_sent_metadata`: subjects/attachments only). It does not write. Zero spanned cards tell you to approve and defend first.
- `referees` prints at most seven people for a posting. Rank is local (hiring-firm overlap, shared words, note, timeline, existing last-contact time, a coauthor flag, and a name already on an ingested pubs record unless `DOSSIER_REFEREE_PUBS=false`). It does not call a model. Under a name it may print up to two claims they could speak to. People come from `--people` / `DOSSIER_PEOPLE`, or from Twenty when both API env vars are set. That Twenty read sends a fixed people query, not the corpus. No people source exits without ranking. A policy file can skip names, warn on scarce names, and alias employers. Every line says to confirm before listing. The command does not write the corpus or Twenty, and it does not send mail.
- Ollama on loopback by default. Text leaves the machine only for a remote LLM: provider `litellm`, or `DOSSIER_LLM_ALLOW_REMOTE` for a non-loopback Ollama. Both are off by default. The CLI prints an egress notice before the prompt is sent. A non-loopback pubs URL is not contacted.
- Ten adapters, registered by hand in `src/dossier/contributions.py`.
- Product page under `website/` and Sphinx guide under `docs/` (`make pages-site`).

## Adapters, as they behave today

| Adapter | What `ingest` does now |
| --- | --- |
| `pubs` | Reads the Zotero collection named in config (`collection`, `zotero_db`) into bibliography records: title, authors, year, journal, DOI, abstract. A JSON fixture still loads in tests. It does not parse PDFs and it does not embed a library. With no collection set, a loopback `POST /search` can still supply rows. |
| `chatgpt` | Reads a ChatGPT export zip or folder (`conversations.json`), or `chatgpt.messages` from a DuckDB file you already have. Short replies are skipped. It does not unpack the zip into the repo. |
| `linkedin` | Reads `positions`, `education`, `skills`, and `publications` from that same warehouse. It skips the rest of a LinkedIn archive. |
| `applications` | Walks one folder whose name contains “job application” (or is `applications`). Cache directories and junk names are skipped. Text files are stored. Other files are inventory lines only; PDF bytes are not read. Stops after `DOSSIER_APPLICATIONS_MAX_FILES` (default 2000) kept files and prints a stderr warning. |
| `transcripts` | Reads Cursor `agent-transcripts/*.jsonl` user queries, and JSON blobs in a folder you point at. Binary blobs are skipped. Nothing from these paths is written to git by the adapter. |
| `slack` | Seeks Glen-touched rows in warehouse `slack.*`, or reads a Slack export zip or folder (`users.json` plus channel JSON) for `DOSSIER_SLACK_USER_IDS` and display-name matches. Applies diversity quotas. Does not copy a channel into git. |
| `mbox` | Seeks Thunderbird Gloda metadata (activity folders, sent+documents). Newsletter-style folders, trash, spam, and drafts drop. Admin, budget, and finance stay. Fetches **one** allowlisted mbox body under a size cap via rollup `parse_message` (stdlib fallback). Never streams IDDRI or Sent Mail. An exported folder stops after `DOSSIER_MBOX_MAX_FILES` (default 40). |
| `meetings` | Seeks a TranscriptX library (or a folder of JSON plus speaker-map sidecars) for meetings where you are a named speaker. Stores your turns, under the usual lenses, and applies seeker quotas. Does not import the TranscriptX package or copy the library. Placeholder `SPEAKER_00` labels, ignored speakers, solo notes, conflicted copies, `__inbox` duplicates, and directories such as `imports` and `metadata` are skipped. |
| `employer` | Walks every folder named in `DOSSIER_EMPLOYER_PATHS` or `[employer] paths`. A filter (on by default) skips cache trees, junk types, hashed names, and older copies of the same file, then stores text. Other kept files are inventory lines only. When the provider is on, a second pass may drop folders from their names. `~/Documents` itself is ignored. |
| `git` | Repos in `DOSSIER_GIT_PATHS` or `[git] paths`, or the path you pass to `ingest`. Stores the subject, date, and a name-only file list. `DOSSIER_GIT_USER` or `[git] user` keeps one author. No patch bodies. No home-directory scan. |

LinkedIn expects the warehouse schema produced elsewhere (see [prior art](prior-art.md)). ChatGPT and Slack use that warehouse, or an export zip. Point `DATA_DUMPS_WAREHOUSE` at `catalog.duckdb`.

## Not in this version

See [roadmap](roadmap.md) for 0.9→1.0 user testing. Still out of 0.9:

- A separate pubs server. `ask.pubs` can still call loopback `/search` for one answer and does not write those hits. Ingest does not embed hoops or ocean.
- LanceDB, sqlite-vec, or a second search product. Vectors are float blobs in `evidence.db`.
- A PDF or JSON Resume renderer. `tailor` writes markdown under `data/drafts/`. France Travail and portal CVs stay outside this repo.
- A plugin loader.

## Tests

`uv run pytest` uses synthetic rows only. Fixtures live in `tests/fixtures/`. Do not add real mail, dumps, or PDFs to the tree. `make prove` is local-only against sources on disk.
